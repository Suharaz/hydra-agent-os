2. Two-Speed Execution Architecture

HOT EXECUTION LANE (Code Only • 0 LLM Calls • Microseconds) Deterministic
Feed Hub (Raw WebSockets + REST)

Multiplexes real-time market data across venues with L2 orderbook synchronization:

  • 3 Futures Sockets: /public, /market, /ws (probe-selected)
  • Spot Streams: @aggTrade, @bookTicker, and Spot WS-API

COLD SUPERVISORY LANE (LLM • Minutes/Hours) OpenRouter
Five Cold-Lane Agents

Each agent runs on its own OpenRouter model, configured via agents.yaml:

  • Commander (claude-fable-5.1): Classifies market regimes → updates engines.yaml
  • Supervisor (deepseek-v4-pro): Evaluates risk → writes tighten-only state/limits.json
  • Treasurer (gpt-5.6-sol): Capital allocator → sets state/budgets.json
  • Coach (gpt-6-astra-pro): Reviews fill slip → fine-tunes engine parameters
  • Sales (deepseek-v4-pro): Monetizes alpha → updates x402 feed & drafts square-post
LLM Daily Budget Gates

Cold-lane scheduler enforces graceful degradation against daily spending limits:

  • 70% Spend: Shadow models disabled
  • 80% Spend: Coach and Sales agents paused
  • 90% Spend: Treasurer agent paused
  • 100% Spend: Commander paused (Supervisor is NEVER gated)
Shadow A/B & Settings Panel

Operator assigns a parallel shadow_model. Decisions are logged without execution to compare metrics:

  • Cost (USD) & Latency (ms)
  • Schema-valid & Tool-rejection rates
  • Agreement % between Primary and Shadow
  • Engine PnL attributed 1 hour post-decision
  • One-click hot promotion: Shadow → Primary
x402 Seller & MCP Bridge

Separate port (8788) serves monetized signal catalog. Binance MCP bridge provides OAuth 2.0 PKCE tool discovery with client-side read-only whitelist.
